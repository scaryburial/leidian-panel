# ADeep 开发日志 / 二次开发指南

> 一个 Android 原生小应用：常驻悬浮窗显示 DeepSeek API 账户余额与今日消费。
> 本文档面向接手二次开发的同学，说明架构、构建方式、扩展点与版本变更。

---

## 一、这是什么

- 悬浮窗实时显示 DeepSeek API 余额（默认 30 秒刷新，可配 5/10/30/60/300 秒，点按立即刷新）。
- 附带「今日消费」估算、开机自启、电池优化豁免、无障碍保活。
- 界面与悬浮窗使用《狐妖小红娘》人物素材（暗色科技风）。

## 二、技术栈与约束

- 语言：Kotlin；构建：Gradle 8.14.4 + AGP 8.13.2；compileSdk 36 / minSdk 26 / targetSdk 34。
- **零第三方依赖**：不用 AndroidX / OkHttp / 协程。网络用 `HttpURLConnection`，JSON 用系统 `org.json`，并发用 `ScheduledExecutorService` + `Handler`。这保证了构建时几乎不依赖远程仓库。
- UI 全部用系统控件 + 原生主题（`@android:style/Theme.Material` 派生），不引入 Material Components。

## 四、核心数据流

1. `MainActivity` 保存 API Key / 刷新间隔 / 自启开关到 `Prefs`（SharedPreferences）。
2. `OverlayService` 是前台服务，`onCreate` 里通过 `WindowManager` 添加 `TYPE_APPLICATION_OVERLAY` 悬浮窗，并用 `ScheduledExecutorService` 定时执行 `doRefresh()`。
3. `doRefresh()` → `BalanceApi.fetch(key)` 请求 `GET https://api.deepseek.com/user/balance`（`Authorization: Bearer <key>`），解析 `is_available` 与 `balance_infos[0]`。
4. 结果经 `DailyUsage.update()` 估算今日消费后，通过 `Handler` 回到主线程更新悬浮窗（数值变化时切换头像、卡片描边高亮）。

## 五、余额与「今日消费」口径

- 余额接口返回：`{ is_available, balance_infos:[{ currency, total_balance, granted_balance, topped_up_balance }] }`。
- **DeepSeek 没有用量接口**，所以「今日消费」是估算：
  - 每天第一次刷新时，把当时的余额记为当日基线；
  - 今日消费 = `基线 − 当前余额`（下限 0）；
  - 余额上涨（充值）时把基线重置为当前值。
- 局限：当天若 App 未运行，0 点到首次刷新之间的消费统计不到；充值当日会清零重算。

## 六、权限说明

| 权限 | 用途 |
|---|---|
| INTERNET | 请求余额接口 |
| SYSTEM_ALERT_WINDOW | 悬浮窗 |
| FOREGROUND_SERVICE(+_SPECIAL_USE) | 前台常驻服务 |
| POST_NOTIFICATIONS | 前台服务通知（Android 13+） |
| RECEIVE_BOOT_COMPLETED | 开机自启 |
| REQUEST_IGNORE_BATTERY_OPTIMIZATIONS | 申请电池优化豁免（防杀） |

崩溃日志通过 **MediaStore** 写入 `Download/阅读备份/ADeep_crash_<时间>.txt`，**无需任何存储权限**（Android 10+）。

## 七、构建

### 一键构建（推荐）
```bash
cd deepseek-balance-overlay
./build.sh            # 需 root；自动装 JDK17、下 Android SDK、生成签名、编译
# 产物：$HOME/workspace/dist/余额悬浮窗.apk
```

`build.sh` 按架构自适应：
- **x86_64**：Android SDK 取 Google 官方源，build-tools 原生工具直接可用。
- **aarch64**：Google 的 `dl.google.com` 常不可达，SDK 改取腾讯镜像；build-tools 里的 `aapt2/aidl/zipalign` 只有 x86_64 版，替换为 GitHub `Commit451/android-arm-build-tools` 的 arm64 版本。

可覆盖变量：`SDK_ROOT` / `OUT` / `KS`（签名密钥）/ `STORE_PASS` / `KEY_ALIAS` / `KEY_PASS`。

### 手动构建
```bash
export ANDROID_HOME=/opt/android-sdk
./gradlew :app:assembleRelease \
  -PRELEASE_STORE_FILE=/opt/balance-overlay.jks \
  -PRELEASE_STORE_PASSWORD=balance123 \
  -PRELEASE_KEY_ALIAS=balance \
  -PRELEASE_KEY_PASSWORD=balance123
```
签名密钥：alias `balance`，口令 `balance123`（默认值，见 `build.sh`；正式发布请自行更换并妥善保管，更换后无法覆盖安装旧版）。

## 八、二次开发扩展点

- **改刷新间隔选项**：`Prefs.INTERVAL_OPTIONS`。
- **改悬浮窗样式**：`OverlayService.addOverlay()`（头像、字号、内边距、卡片描边）与 `render()/flash()`。
- **换人物素材 / 图标**：替换 `res/drawable/char_*.jpg` 与 `app_icon.jpg`；悬浮窗头像列表在 `OverlayService.AVATARS`。
- **接入余额之外的接口**：仿 `BalanceApi` 加新的 `object XxxApi`，在 `OverlayService.doRefresh()` 里调用。
- **改主题配色**：`res/values/colors.xml` 与 `drawable/btn_*`、`panel_tech`、`bg_scrim`。
- **发布前务必**：更换签名密钥、改 `applicationId`（如需与现有安装共存）、按需关闭 `App.kt` 里的崩溃日志落盘。

## 十、已知限制

- 今日消费为余额日差估算，非官方用量数据。
- 小米/MIUI 上需手动开启「自启动」与「省电策略：无限制」，开机自启与防杀才可靠。
- 无障碍保活只是降低被清理概率，不保证绝对不被杀。
- 悬浮窗依赖 `SYSTEM_ALERT_WINDOW`，需用户手动授权。
